# W4.3: runtime extraction before spec migration

Recorded 2026-09-10.

## Why this document exists

W4.3 as written in `urui-extraction-plan.md` says:

> Move the 6 whole Ace specs + the generic halves of `editor-surface`,
> `lifecycle`, `tabs`, `shortcut-boundaries`, and the generic part of
> `ace-assets` to `urui/tests/browser/real/`, retargeted at the fixture.

That presumes the generic browser runtime already lives in urui. It does
not. W3.5 as executed extracted the **contract** — `window.urui`, the hook
table, `urui.boot`, and the Ace editor adapter — while every generic
*behavior* (document tabs, refs, explorer views, docs tabs, the file tree,
session load/save, the Clay file operations, the shortcut dispatcher) stayed
in `graph-viz/desk/lib/gviz-web.hoon ++app-js`. `tests/fixture/lib/
urui-fixture-web.hoon ++app-js` only recorded hook calls, so the fixture had
no editor, no tabs, and no persistence to test against.

Retargeting `tabs.spec.js` or `lifecycle.spec.js` at that fixture would have
meant writing a second implementation of behavior graph-viz already has.
The decision (2026-09-10) was to **extract the runtime first**, so both
consumers share one implementation, and only then move the specs.

## Stage 1, as landed

`urui-js.hoon` gains `++runtime`, emitted inside `++core` as
`createRuntime(options)` and published as `window.urui.runtime`. It reads
policy from `window.URUI_CONFIG` and reaches the frame through the ids
`urui-shell` fixes (`#workbench`, `#workspace`, `#splitter`,
`#explorer-resizer`, `#explorer-collapse`, `#help-panel`, `#close-help`,
`#clay-error-modal`, `#clay-error-message`, `#close-clay-error`) plus the
`data-role` attributes W3.6 added. Nothing in it names a consumer; the
Hoon arm `test-shell-runtime-contract` asserts that directly.

Consumer-supplied `options`:

| option | meaning |
|---|---|
| `elements` | overrides for the panes and status lines a consumer names itself (`explorerPane`, `editorPane`, `resultPane`, `editorStatus`, `resultStatus`) |
| `editors` | array or thunk of Ace adapters to resize and re-theme |
| `onChange` | called whenever a persisted value moves — the consumer's `queueSaveSession` |
| `onResize` | extra work on window resize |
| `onHelpOpen` | run before the help panel takes focus |

Returned surface: `elements`, `clamp`, `refreshEditors`, `theme`
(`valid`/`selected`/`apply`/`media`/`systemChanged`), `status`
(`set`/`node`), `layout` (`paneWidth`/`setPaneWidth`/`explorerWidth`/
`setExplorerWidth`/`maxExplorerWidth`/`explorerOpen`/`setExplorerOpen`/
`apply`), `dialogs` (`helpIsOpen`/`setHelpOpen`/`showError`/`hideError`/
`errorIsOpen`), and `wire()`.

`wire()` is separate on purpose: every accessor above is callable without
it, so a consumer that wants different event handling simply never calls
it. Graph-viz calls it; the fixture calls it.

### Consumer changes

Graph-viz deleted `refreshEditor`, `validTheme`, `applyTheme`,
`systemThemeChanged`, `setHelpOpen`, `showClayError`, `hideClayError`,
`currentPaneWidth`, `currentExplorerWidth`, `maxExplorerWidth`,
`setExplorerWidth`, `applyExplorerLayout`, the `explorerOpen` variable, the
`themeMedia`/`themes`/`minExplorerWidth`/`explorerDividerWidth`/
`clayErrorReturnFocus` bindings, and eleven listener registrations. Each
call site keeps its old name as a one-line alias, so the diff is confined
to the definitions.

The fixture gained the two generic toolbar controls the runtime wires — the
theme select and the Help button, exactly as `desk/tests/lib/
urui-shell.hoon` already modelled them — and builds a runtime at boot.

## Running the Hoon lib suites without a ship

`bin/hoon-test.js CONSUMER TEST_FILE [arm ...]` compiles one
`/tests/lib` file through `vere eval` and prints which arms returned a
non-empty `tang`. It walks the file's `/-` and `/+` imports depth first,
binding each as `=+  ^=  face`, and composes `lib/test.hoon` into the
subject so `expect` resolves. A shared library is taken from the
consumer's own copy when it has one, otherwise from urui.

```
node bin/hoon-test.js /mnt/mars/gitrepos/graph-viz desk/tests/lib/gviz-web.hoon
node bin/hoon-test.js /mnt/mars/gitrepos/urui desk/tests/lib/urui-js.hoon
```

Two limits, both reported rather than silently mis-run:

- a suite using `/*` reads its corpus out of clay, which does not exist
  here — `conform`, `e2e`, `coord`, `order`, `rank` and `route` need
  `-test` on a ship, and the runner exits 2 saying so;
- `/tests/app` suites need the Gall harness and do not compile this way.

`bin/hoon-parse.js FILE ...` covers the gap the sweep leaves: it `ream`s
a file through `vere eval` and reports whether it parses at all. A
substring sweep cannot see a syntax error, and one recurs — a tape
carrying a literal brace. `"...{..."` opens interpolation; the escape is
`\{`, as `tests/lib/ast.hoon` and `tests/lib/route.hoon` have always
written it. Run it on every Hoon file an edit touched.

Since stage 4 there is a third limit: `graph-viz/desk/tests/lib/gviz-web.hoon`
no longer finishes here. Each of its nine arms recompiles `page:web`,
`css:web` and `javascript:web`, and the runtime cord those embed is now
about 2,400 lines. Run that file with `-test` on a ship. Its arms are
plain substring checks over the three assets, so the equivalent local
check is to compile once and sweep the needles — the script used
throughout this refactor, which reports a needle that a positive
assertion cannot find or that a negative assertion can — followed by
`bin/hoon-parse.js` on the file itself.

This does not replace the desk gate. It closes the loop between an edit
and the arms that edit can break, which for this refactor is
`desk/tests/lib/gviz-web.hoon` and urui's seven lib suites.

### Caught by it

`test-persistence-export` broke in stage 2 and was fixed here. It asserted
the session record still carries `"activeDotTabId,"` and
`"activeSvgTabId,"` — object shorthand. Moving the tab state into the
runtime turned those into `activeDotTabId: runtime.tabs.activeId('dot')`,
so the shorthand disappeared while the persisted key did not. The needles
are now `"activeDotTabId:"` and `"activeSvgTabId:"`, which is what the
arm was always about.

## Stage 2, as landed

`$doc-kind` gained `leaf=@ta`, the clay extension a document is stored
under, leaving `ext` as the suffix a tab label shows. They differ whenever
a mark is reused for a format that names itself differently — graph-viz
writes DOT under `%txt` and labels tabs `.dot`, which is what forced the
split. Before this, `ext` was inert: the config emitter published it and
nothing read it, while the real leaf lived in `gviz-clay.hoon` where the
runtime could not see it. Stage 5 needs `leaf` again to build clay paths
from the config instead of the app's hardcoded kind→extension map.

`++runtime` gained a document-tab section: one store per `config.kinds`
entry, the strip markup, dirty marks, keyboard navigation, drag and drop,
`moveTab`, the close guard, and the `+` control. A consumer supplies only
what differs between its kinds, through `options.tabs[kindName]`:

| hook | when |
|---|---|
| `defaults(options, source)` | extra fields for a new tab |
| `dirty(tab)` | override the `source`/`cleanSource` comparison |
| `onCapture(tab)` | copy live editor state into the tab |
| `onActivate(tab, {previousId, …})` | after the active id moves, before render |
| `afterActivate(tab, …)` | after render and persistence |
| `onClose(tab)` | after the tab leaves the store |
| `empty()` | the store just emptied |
| `add` | label for the `+` control, or absent for none |

Plus three shared options: `onTabsRendered(kind)`, and
`explorerOrder()`/`onExplorerOrder(order)` so `moveTab` can keep serving
the explorer strip until stage 3 absorbs it.

`moveTab` and `setList` reorder **in place**, so `runtime.tabs.list(kind)`
is a stable reference a consumer can hold — graph-viz's `dotTabs` and
`svgTabs` are now exactly that, which kept 45 call sites unchanged. The
scalars (`activeDotTabId`, `nextDotTab`, and their SVG twins) could not be
aliased and became explicit `runtime.tabs.activeId`/`setActiveId`/`next`/
`setNext` calls.

## Stage 3, as landed

`++runtime` gained the explorer: one tab strip holding the permanent file
trees named by `config.permanentViews`, documentation tabs backed by
iframes, and reference tabs mirroring an open document — plus the clay
file tree, its context menu, and the `doc.toc` format.

The `['docs', 'graph viz']` title-noise set became
`['docs', config.appId.title.toLowerCase()]`, and `loadDocsTree` fetches
`${config.appId.base}/doc.toc` instead of a literal route. Two conventions
carry the rest: a permanent view is `${kind}-files` and owns
`#${view}-tree`, and a kind's Add Ref control is `#add-${kind}-ref`. Both
already held for graph-viz and the fixture. The empty-tree message finally
names the right thing — `No /txt files found.` comes from `kind.leaf`,
which stage 2 added.

Stage 2's escape hatch is gone: `moveTab`'s explorer branch reorders the
explorer's own `explorerOrder` and calls `syncExplorerTabOrder` directly,
so `options.explorerOrder`/`onExplorerOrder` no longer exist. `captureTab`
now syncs a reference from its parent, and `renderTabs` updates the Add Ref
controls, so those two no longer travel through consumer hooks either.

Two new consumer options, both networking, both temporary:
`options.browse(kind)` answers a list of clay paths and
`options.openFile(kind, path)` opens one. Stage 5 absorbs them. Graph-viz
keeps `browseClayNode` — the recursive walk that turns one browse endpoint
into that path list — for the same reason.

`docsTabs` and `refTabs` reorder in place like the document stores, so
graph-viz holds them by reference.

## Stage 4, as landed

`config.slots` stopped being published data and became the thing that
drives the record. `++runtime` now owns one localStorage envelope under
`config.appId.storageKey`, written and read slot by slot in the order the
config lists them. Each slot names the json key already on disk, so an
existing `graph-viz.session.v1` record keeps loading with no migration —
the point of §2.5.

- `readSlot` answers urui's own slots from the shell's live state: the
  kinded shapes (`%tabs`/`%active`/`%next`) come from the document
  stores, the rest by key from layout, explorer and theme.
- A slot marked `app` goes through `options.session.read(key)` on save and
  `options.session.validate(key, value)` on load. Graph-viz has three:
  `source`, `view`, `preferences.autoRender`.
- A dotted key nests — `preferences.theme` writes `{preferences: {theme}}`,
  not a flat key.
- `load()` validates the whole record, **applies** urui's half, and returns
  the record so the consumer can read its own slots. Graph-viz's boot lost
  twenty lines of restore.
- `%next` counters floor to the highest saved id, so `text-7` forces the
  next tab to at least 8 however stale the saved counter is.
- A per-kind `validate(candidate, base, ids)` hook supplies the extra
  fields a saved tab carries. `ids` is the map of already-accepted ids per
  kind, which is how graph-viz drops an SVG tab's `sourceDotId` when the
  DOT tab it points at did not survive.

The shared validators (`validateSource`, `sourceByteLength`, path and
label validators) and the shared-source url parameter came along.
`decodeSource` refuses outright when `config.shareParam` is empty, and its
messages name the configured parameter rather than a format.

`changed()` now falls back to `queueSaveSession()` when no `onChange` is
supplied, so a consumer gets debounced persistence for free; `wire()`
registers `beforeunload`.

`test-persistence-export` was restated: graph-viz's half of the record is
declared, not written, so the arm asserts against the emitted config —
`"shareParam":{"name":"dot","max":12288`, `"key":"dotTabs"`, and the two
`"owner":"app"` slots.

Verified: graph-viz **57 Chromium passed** — including `lifecycle.spec.js`'s

## Stage 5, as landed

`++runtime` composes two new cord arms, `++files` and `++shortcuts`, into
its lexical scope. `options.browse` and `options.openFile` are gone.

`runtime.files` exposes `browse(kind)`, `load(kind, path?)`, `save(kind)`,
and `delete(kind, path?)`. Browse refreshes the tree, walking the configured
browse endpoint recursively. Routes replace `{kind}` using the kind name;
header transport preserves the existing raw-text request and configured
path/overwrite headers. Body transport sends JSON containing `path` as
segments, `source` as text, and `overwrite` as a boolean. Kind `leaf`/`ext`
continue to control tree messages and document labels; the backend retains
its existing default-leaf behavior for user-entered paths.

Load reuses an already-open path. Save captures the current tab, checks its
stored baseline, asks before overwriting a changed copy, and retries a new
path's 409 response only after confirmation. Successful saves update the
clean baseline, references, tab strip, session and tree. The runtime also
wires the per-kind browse/load/save controls and both context-menu actions.

Optional `options.files[kind]` hooks supply application policy and feedback:
`validate(source)`, `canSave(tab)`, `status(label, action)`, `loaded(tab)`,
`saved(tab, source)`, and `error(cause, action)`. Shared source validation
runs before the optional validator. Graph-viz supplies DOT/SVG status and
preview feedback and updates SVG's separate edit baseline after save.

`runtime.shortcuts.register(command, handler)` installs handlers for
`config.shortcuts`; `wire()` installs the capture-phase dispatcher. Escape
closes Help, then the Clay error, then the file menu, restoring focus at
each step. Matching requires the configured modifier set, so Ctrl+Alt+S
continues to reach Ace. Ctrl and Meta both match primary bindings.
`when: editor` and `no-editor` use Ace focus; `preview` uses the consumer's
`options.shortcuts.preview(event)` availability predicate, including while
Ace is focused. Unclaimed editor keys remain with Ace; outside editors,
`options.shortcuts.onKeydown(event)` may claim application context actions
by returning true. Tab-strip, divider and menu navigation retain their
existing runtime listeners.

Graph-viz's `handleShortcut` now only registers five commands in nine lines.
Its visual-selection Escape/Delete/Backspace handling is the contextual
hook. The boot API forwards `files` and `shortcuts` to the runtime. Fixture
editor mounting and replacing its public trace hooks remain Stage 6.
